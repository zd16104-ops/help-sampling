# 同步问题日志审查规则（巴松措采样系统 V1）

本文用于排查"手机收不到任务 / 数据传不上去 / 同步失败"。日志有两个来源：
**手机端**（APP「我的」页 → 复制诊断日志 / 分享日志文件 CSV）和**管理站**（📋 诊断日志 → 可筛选、可导出 CSV）。

---

## 一、每次同步的完整日志骨架

一次成功的同步，手机端应出现以下序列（按时间从早到晚）：

```
SYNC_BEGIN   {"network":"cellular|wifi|none","pendingRecords":N,"pendingTracks":M,"pendingLogs":K,"online":true|false}
SYNC_TASKS   {"tasks":N}          ← 关键：服务器返回给手机的任务数量
SYNC_START   （有离线行程时）       ← 补报行程开始
SYNC_TRACK   （有轨迹时，失败才记录）
SYNC_RECORD  （记录上传失败才记录）
SYNC_END     {"pendingRecords":…,"pendingTracks":…,"pendingLogs":…}
```

**审查第一问**：`SYNC_TASKS` 的 `tasks` 是多少？
- `tasks ≥ 1`：任务已到手机。若界面上看不到 → 是**显示问题**（列表刷新/过滤），不是同步问题。
- `tasks = 0`：服务器认为该手机所属采样员没有任务 → 到管理站核对"下发任务的采样员"是否等于手机"我的"页里的账号。
- 没有 `SYNC_TASKS` 行 → 同步没走到任务这一步，见下表。

## 二、错误关键字 → 原因 → 处理（对照表）

| 日志关键字 | 含义 | 原因 | 处理 |
|---|---|---|---|
| `SYNC_SKIP_OFFLINE` | 检测到无网络，主动跳过同步 | 正常现象（离线时数据保存在手机） | 联网后自动补传；无需处理 |
| `Unable to resolve host` | 域名解析失败 | 运营商 DNS 在移动网络下解析不了 `bsc.gpsgps.online` | 已加 DoH 回退（223.5.5.5）；升级 APP ≥1.2.4 后应消失 |
| `Failed to connect … :443` | 解析成功但连不上服务器 | 服务器重启中 / 防火墙 / 运营商拦截 / 弱信号 | 稍后重试；多次出现检查服务器是否在线、443 是否放行 |
| `timeout` / `超时` | 连接或读取超时 | 弱网、服务器慢 | 稍后重试；检查服务器负载 |
| `设备登录已过期` | 令牌失效（HTTP 401） | 服务器 config 被重建或令牌过期 | 下一行应有 `LOGIN_REFRESH` 或 `AUTO_RELOGIN` 自动恢复；若没有，升级 APP ≥1.2.4 |
| `HTTP_FAIL /api/v1/mobile/…` | 单次请求网络失败（新日志，v1.2.4+） | 见后面的具体异常 | 与上面三类对应 |
| `服务器内部错误`（SYNC_RECORD） | 记录上传被服务器拒绝（HTTP 500） | 服务端异常 | 把服务器控制台报错发开发者；新版本服务器会返回具体原因 |
| `SYNC_START task=… HTTP423` | 任务被另一台手机锁定 | 同任务在别的手机开始了 | 管理站"人工解锁设备" |
| `账号不存在或已停用` | 采样员被停用 | 管理端停用了该采样员 | 管理站重新启用 |
| `手机尚未激活` | 设备未绑定 | 换手机/清数据后未扫码 | 管理员生成新激活二维码扫码 |

## 三、手机端日志里每行的字段

```
2026-08-28T23:57:52.757+08:00 [info] SYNC_BEGIN {"network":"cellular","pendingRecords":0,"pendingTracks":14,"pendingLogs":1,"online":true}
```

- `network`：`wifi` / `cellular`（移动数据）/ `none`（无网络）。**移动网络失败但 WiFi 正常 = DNS 或运营商拦截问题（见上表第 2 行）。**
- `pendingRecords`：还没传上去的采样记录条数；**一直大于 0 = 上传失败**（结合 SYNC_RECORD 错误行看原因）。
- `pendingTracks`：没传上去的轨迹点数；**一直大于 0 = 行程补报失败**（老版本离线完成的行程会永久卡住，已修复；升级后第一次同步会自动清掉）。
- `pendingLogs`：待上传的日志条数（日志本身上传失败不影响采样数据）。
- `online`：APP 判断的网络状态。

## 四、管理站日志（📋 诊断日志）补充字段

管理站每条日志多两列：**采样员ID**、**设备ID**、**服务器接收时间**。

- 服务器只收到 `SYNC_BEGIN` 却没有后续行 → 请求中断（弱网）。
- 收到大量 `SYNC_BEGIN` 连续爆发（同一秒多条）→ 手机端多线程重复同步（正常，已限流）。
- 没有任何来自某设备的日志 → 该手机根本连不上服务器（DNS/网络层），看手机端日志。

## 五、标准排查流程（遇到"同步不了"时按顺序做）

1. **手机"我的"页**：看网络类型与版本号；点"复制诊断日志"发出来。
2. **日志里找 `SYNC_TASKS`**：有 → 任务已到手机（看列表刷新）；无 → 继续。
3. **找错误行**（error/warning 级别），对照第二节表格定位。
4. **管理站**：确认该采样员账号、设备存在且启用；`待采样任务` 数量 > 0。
5. **服务器**：浏览器打开 `https://bsc.gpsgps.online` 能出登录页 → 服务在线；不行 → 重启 `BscSampling` 服务。
6. 仍然无法解决 → 把**手机日志 CSV + 管理站日志 CSV + 服务器控制台报错**一起发给开发者。

---

## 六、健康基线（正常状态长什么样）

- 每次联网触发同步：`SYNC_BEGIN → SYNC_TASKS（tasks≥0）→ SYNC_END`，间隔几秒。
- `pendingRecords / pendingTracks / pendingLogs` 最终归 0。
- 离线时只有 `SYNC_SKIP_OFFLINE`，不报错。
- 15 分钟一次的 WorkManager 后台同步 + 网络恢复即时同步。
